# 智能问答与技能库（控制台）

控制台侧边栏「总览」下有两页：**智能问答**（`#/chat`）与**技能库**（`#/skills`）。
问答会真实调用模型并**按你选择的 API Key 计费**，模型可以调用网关自己的后台接口来回答问题。
设计与取舍见 `docs/design/m32-console-smart-chat.md`；内联表单见 `docs/design/m35-inline-forms.md`，
可交互的沙箱页面见 `docs/design/m34-ui-bridge.md`。

## 1. 开始一次问答

「智能问答 → 新建会话」需要选择三样东西：

| 选择 | 说明 |
| --- | --- |
| 计费账户 | 从「账户」页已有的账户里选 |
| API Key | 该账户下的 Key；**明文密钥不会交给浏览器**，服务端按 id 解析并校验 |
| 模型 | 只列出这个 Key 真正可路由的模型（与 `GET /v1/models` 同一套授权与路由判断）；不支持工具调用的模型会被标注 |
| MCP 令牌 | 本会话以哪个令牌的身份执行；工具面与可写范围都由它的 scope 决定，见第 5 节。只列出仍然可用（active 且未过期）的令牌，没有令牌就无法创建会话 |

绑定之后，输入框里提问即可。回答是流式的，可以中途「停止」；停止或断线时**已经生成的部分会保存**，
已经花掉的费用照常计费。

首版**只有 `admin` 角色可以创建会话、提问和生成技能草稿**。`viewer` 可以浏览自己的会话、
管理自己的技能，但不能绑定计费 Key、不能发起计费请求——Key 列表对 viewer 是可见的，
如果只校验 Key 本身是否有效，就等于把「能看」变成「能花」。服务端在**每一步模型调用**前
都会重新校验登录会话、角色、账户与 Key 的状态与归属。

## 2. 计费、日志与隐私

一次提问可能包含多步模型调用（查数据 → 再查一步 → 总结），**每一步都是一条独立的计费请求**：
配额、限流、在途额度、结算、账本、请求日志、hooks 全部走与普通流量完全相同的流程
（复用同一个 `/v1/responses` 处理器，没有任何并行的计费实现）。

在「请求日志」页可以这样找到它们：

- **客户端**：`console`
- **会话**：聊天会话 id（即请求的 `prompt_cache_key`）
- 每步一个 `request_id`，可用消息下方的「复制请求 id」拿到

与普通流量唯一的区别是**内容录制**：问答的正文、技能内容、模型输出与工具结果
**不会**写进请求日志、存储响应或 hooks，这些入口对同一实例的**其他管理员**是可见的。
请求日志里只保留身份维度、token、成本与状态；技能相关的审计只记录操作与不透明 id，
不记录技能名与指令。

需要清楚的一点：**「应用内私有」不等于「不离开本机」**。技能指令与你的问题会随请求
发送给所选的上游模型供应商，这是使用技能的前提。

费用显示在两处：消息下方的脚注（tokens、成本、收费，与请求日志同源，来自 `usage_records`），
以及「请求日志」页。

## 3. 输出形态

- **Markdown**：标题、列表、引用、表格、代码块、行内代码/强调/链接。渲染器只做安全子集，
  文本一律按纯文本插入，模型给的原始 HTML 不会进入控制台页面。
- **图表**：模型输出 `chart` 代码块的 JSON 规格，控制台**自己画 SVG**（离线、不执行模型代码），
  并提供数据表、来源图注与 CSV/SVG 导出：

  ```json
  {"type":"bar|line|area|pie","title":"本月成本","x_label":"模型","y_label":"成本","unit":"USD",
   "categories":["flash","luna"],"series":[{"name":"成本","values":[1.2,0.4]}],
   "source":{"tool":"admin_request","note":"本月 1 日至今天"}}
  ```

  上限为 8 条序列、500 个数据点；越界或规格非法时**退回显示原始规格并说明原因**，不会画一半。
  图表下方会列出本轮实际调用的管理接口，方便你把数字与来源对照——**控制台无法验证模型是否
  如实使用了工具返回的数字**，数据表与来源信息就是给你核对用的。
- **内联表单**（`form` 代码块，M35）：模型需要你提供少量信息时，直接在**对话气泡里**给出一张
  表单，你就地填写、就地提交，回答也就地回灌到这张表单上。不需要点「预览」，不会另开窗口。
  见第 4 节。**需要你给信息时这是模型的默认手段**（M40）：用散文追问、或让你去点预览，都是次选。
- **HTML5 页面**：模型输出 `html` 代码块（内联 CSS/JS），点「预览」在**沙箱 iframe** 里运行；
  `svg` 代码块同样提供预览。默认**禁止加载任何外部资源、禁止发起网络请求**，所以引用 CDN
  图表库的页面不会渲染——控制台会先提示「引用了外部资源」，需要联网时要管理员在配置里打开
  `chat.artifact_allow_network`。
- **可交互的沙箱页面**：与内联表单相对的另一条路——模型输出带表单的整页 HTML，你在预览窗口里
  填写并提交，事件回到**同一个会话**（模型据此继续执行），回答再流式回灌到页面上原地更新。
  这是 M34 的能力，见第 5 节。

## 4. 内联表单：模型在对话里问你要信息（M35，M40 起是默认手段）

模型需要的信息很少时（账户名、区域、数量……），它会输出一个 `form` 代码块，控制台把它**渲染成
对话气泡里的一张表单**。你填完点提交，**这次提交就是一条正常的提问**：模型拿到你填的真实数据继续
执行（可以再调后台接口查），回答边生成边出现在这张表单的状态行里，结束时用界面指令**原地更新**
表单（改文案、把查到的值填回字段、提示信息），会话转录里同时留下这一轮的问答气泡。

**它和第 5 节的沙箱页面是两条路**，各有各的用处：

| | 内联表单（本节） | 沙箱页面（第 5 节） |
| --- | --- | --- |
| 位置 | 直接长在对话气泡里 | 点「预览」开的窗口 |
| 模型给什么 | 一份**字段规格**（JSON） | 一整页 HTML（含它自己的 CSS/JS） |
| 控制台做什么 | 自己造元素、自己渲染 | 沙箱 iframe 里跑模型给的页面 |
| 能做 | 字段、选项、说明、提交与次要按钮 | 自由排版、图表、页面脚本 |
| 安全边界 | 模型只提供数据，**没有标记与脚本进入控制台** | 不透明源沙箱 + 专用通道 |

模型在两者之间怎么选（M40 起写进提示词，有测试钉住）：要几个字段就用内联表单；要一整页自由排版或
页面脚本才用 `html`。同一轮里最多一张表；能查到的事实（账户名、模型名、现有配置）模型自己查，
只有**缺关键参数**（时间范围、目标模型/供应商、要写入的数值）时才问你，并且一次问全、给出可推断的默认值。

### 用起来是什么样

1. 提问；模型直接回一张表单（气泡里带标题、字段与提交按钮，下面是「查看表单规格」）。
2. 填写。**没提交的内容不会丢**：轮次结束后转录会重建，但你已经填的值会被保留。
3. 提交 → 表单变灰并显示「模型正在处理…」，回答的增量实时出现在表单里的状态行。
4. 本轮结束，表单恢复可用，并按模型的指令原地更新（标题改写、字段被填上查到的值等），
   转录里留下这一轮的问答气泡。

- **每次提交都计费**，与手动提问完全相同：一条 `client=console` 的请求，会话 id 相同，
  在「请求日志」页按会话 id 能找到。
- 模型还在回答时提交会**排队**（最多 5 条），本轮结束后按顺序发出，不会并发计费。
- 一次提交的事件体积上限 8 KiB（多字段一起去很容易到），超了会说明原因而不是静默丢弃。

### 模型能表达什么

字段类型只有这些：`text`（默认）、`textarea`、`number`、`select`、`radio`、`checkbox`、`date`、
`note`（在表单里写一句说明，不产生值）。可选/必填、默认值、占位符、帮助文字、选项标签、
数字的 min/max/step 都支持。

**没有 `password` 和 `file`**，而且是明确拒绝而不是降级：

- 表单值会作为一条提问进入会话转录，所以**表单不是收凭据的地方**（第 5 节的口径不变）；
- 文件无法随提交传送。

规格写错时（未知类型、缺 name、选项重复、默认值不在选项里……）控制台**不画半张表单**，
而是保留原始代码块并说明原因——与图表规格非法时的做法一致。

### 界面指令（原地更新）

本轮结束时模型可以给一个 `ui` 指令块，控制台按**白名单**应用到这张表单上：改文本、按 id 设值、
显隐、启用/禁用、聚焦、页内提示、换一块矢量图。没有「注入 HTML」这类能力，也没有任何脚本。

表单里能被指令指到的**只有三样**（这三种 id 都是控制台生成的，因为表单是控制台画的：

| 目标 | 选择器 | 说明 |
| --- | --- | --- |
| 表单本身 | `#form_<代码块序号>` | 对它执行 `disable` 会连同表内所有控件和按钮一起禁用（「这张表用完了」） |
| 字段 | `#f_<name>` | `name` 就是模型在规格里写的字段名 |
| 按钮 | `#b_<name>` | 提交按钮是 `#b_submit`（或规格里 `submit.name` 给的名字），次要按钮是 `#b_<action.name>` |

两点容易踩：

- **表单不一定是 `#form_0`**。序号是这条回答里代码块的顺序，表单前面还有别的代码块（比如一张
  `chart` 表）时序号会跟着变。模型应当按"这张表单是第几个代码块"来写，控制台做的事只是把这个
  序号渲染成 id。
- **`button[type=submit]` 在这里永远匹配不到**。内联表单的按钮是控制台用 `createElement` 造的
  `<button type="button">`（真正的 submit 会让浏览器重载页面），`type=submit` 只属于第 5 节那种
  模型自己写的整页 HTML。写错了不会静默失败：表单底部会显示"部分未生效：… 没有节点匹配 …"。

`message` 的落地位置是这张表单卡片**顶部**的一条提示条（`.aigw-msg`），级别 `info|ok|warn|error`
只改左侧色条——这是为了让"模型说它做完了"这件事在长表单上也一眼看得到，而不是被排在
「查看表单规格」下面（那是卡片最后一行）。

## 5. 可交互的沙箱页面：填写表单后模型继续执行

模型需要你提供信息时（选哪台设备、要哪段时间、用哪个账户名……）也可能输出一个带表单的 HTML5
页面。你在页面里填写并提交，**这次提交就是一条正常的提问**：事件回到同一个会话，模型拿到你填的
真实数据后继续执行（可以再调后台接口查、再算），回答边生成边回灌到页面上并**原地更新**界面。

### 用起来是什么样

1. 提问；模型输出一个 `html` 代码块 → 点「预览」。
2. 预览窗口上方出现一条工具栏，右侧显示桥接状态（`等待页面握手` → `已连接 · 本页已提交 n/40`）。
3. 在页面里填写、点页面自己的提交按钮（或标了 `data-aigw-send` 的按钮）。
4. 工具栏计数加一，状态变成「模型正在处理…」；回答边生成边流进页面，结束时界面原地更新，
   会话转录里同时留下这一轮的问答气泡。

- **每次提交都计费**，和手动提问完全一样：一条 `client=console` 的请求，会话 id 相同，
  在「请求日志」页按会话 id 能找到它们，token 与费用照常结算。
- 界面**不会自动重载**：模型给出新的整页版本时，工具栏出现「加载新版本」，由你决定要不要换
  （换页会清空你在当前页面上填的内容）。
- 「停止生成」在工具栏上，中断与恢复的规则和普通提问一致：已经生成的内容保留，已经产生的费用照常。

### 界面能做什么、不能做什么

页面在沙箱 iframe 里运行（无 `allow-same-origin`、无表单导航、默认无网络），只能通过一条
**专用通道**和控制台对话：

- 页面**看不到**控制台的登录态、Cookie、localStorage，也不能自己发管理接口请求；
- 页面里的文字**不能提权**：它只是你的输入数据，权限仍然只由会话绑定的 MCP 令牌 scope 决定，
  危险接口照样要 `confirm=true`（而 `confirm` 依然是模型的自我约束，不是人工确认，见第 6 节）；
- 模型返回的 `ui` 指令块是**白名单操作**（改文案、按 id 设值、显隐、启用/禁用、聚焦、页内提示、
  换一块矢量图），没有「注入 HTML」这类能力，也不会执行页面里的字符串。

### 限额（防止一次预览花掉很多钱）

| 限制 | 默认 | 说明 |
| --- | --- | --- |
| 提交最小间隔 | 1.5 秒 | 过密的提交被直接拒绝并说明原因，不会静默丢弃 |
| 单次预览提交次数 | 40 次 | 达到上限后工具栏提示，需要重新预览才能继续 |
| 单次事件体积 | 8 KiB | 表单值（含数组/多选）超过就拒绝 |
| 同一会话在途轮次 | 1 | 模型没答完时提交会排队（最多 5 条），不会并发计费 |

不要用表单传凭据（API Key、密码、MCP 令牌明文）：表单值会作为新一轮提问进入会话转录，
和直接打字没有区别。需要发凭据类操作时，按第 6 节的规则处理。

## 6. 权限与危险操作

聊天没有自己的权限开关：**它就是 MCP 的一个客户端**，能做什么完全由会话绑定的 MCP 令牌
的 scope 决定。

- `query`：只读本账户的用量、余额、账本与请求日志（11 个查询工具）。
- `admin_read`：上面这些，加上后台接口的**只读**部分（写接口返回 `requires scope=admin`）。
- `admin`：全部控制台操作，包括签发 Key/MCP 令牌、赠送或过期额度、备份与恢复、hooks、
  供应商凭据、设置项、删除类接口。**绑定 admin 令牌等同于把管理员凭据交给这个会话。**

其余几点：

- 令牌**不能由聊天自己签发或修改**（除非会话绑定的就是 admin 令牌且你明确要求），
  技能指令也不能提权。
- 令牌是**每次工具调用**重新解析的：在「MCP 令牌」页撤销它、或让它过期，正在进行的
  会话在下一次调用立即失效。这是收回权限的手段。
- **会话头部的令牌徽章可以点击改绑**（`PATCH` 的 `mcp_token_id`）。改绑只换执行身份：
  已加载的技能、消息与计费绑定都不动，工具面在下一次提问时按新令牌的 scope 重新计算。
  升级前创建的会话没有绑定令牌，用这个入口绑上即可继续用，不必重建会话。
- 危险接口仍需 `confirm=true`，但那只是**模型的自我约束，不是人工确认**。绑定 admin
  令牌就意味着允许模型执行不可逆操作，请按需选择 scope，而不是习惯性绑 admin。
- 发凭据类接口（`admin_create_key`、`admin_create_mcp_token`）的明文只返回一次，
  **并且会留在这个会话的记录里**。用完请到对应页面收回或轮换。
- 聊天发起的写入在审计里记为 `mcp:<令牌名>#<id>`，与外部 agent 的写入同格式——它们是
  同一种东西。

## 6.1 模型怎么调用这些接口（M40）

模型看到的**只有工具说明本身**：工具名、一句话描述、参数 schema，以及 `admin_describe` 返回的
`body_schema` 与 `example`。它没有本仓库的文档，也没有历史记忆，所以"说明里没写的字段名"
对它来说就是**不存在**的字段。一次真实故障就是这么发生的：运维要求给某个模型配成本价，
模型查完接口后**拒绝写入**并回复"网关没有公开规则格式，我不猜字段名，否则只能保持配置不变"——
它的判断是对的，因为价格文档走严格解析，猜字段名必然 400。修的办法不是催它"大胆写"，
而是把形状写进工具说明（标准见 `docs/mcp.md` §4.5）。

现在模型侧被明确要求按这个顺序工作（提示词规则 3、4，见 `internal/chat/prompt.go`）：

1. **先看有什么**：不确定接口名先 `admin_endpoints`；
2. **再查怎么调**：写任何配置前必须 `admin_describe`，按返回的 `body_schema`/`example` 写。
   价格规则集还可以先用 `admin_validate_pricing`（只校验、不写库、`admin_read` 权限即可）过一遍，
   把报错原文翻成人话再动手；
3. **形状没给就明说，绝不猜**：如果某个字段确实没有形状说明，模型应当告诉你"拿不到该字段的格式"，
   而不是编一个字段名，也不是因为心虚而整件事都不做；
4. **参数不全先问**：缺时间范围、目标模型/供应商/账户，或要写入的具体数值（价格、限额、权重）时，
   输出一张内联表单一次问清（第 4 节），可枚举项做成下拉、能推断的默认值写进 `value` 并说明。

你在界面上能验证这几点：

- `admin_describe` 的输出会原样出现在这一轮的工具调用里（点开工具调用记录即可看到 `body_schema`）；
- 价格类改动前后可以点开「价格」相关页面核对成本规则与售价；
- 模型如果只说"无法配置"，先让它 `admin_describe(admin_upsert_provider_model)` 再试一次——
  这通常就是它缺的那一步。

## 7. 技能

技能是你写给模型的**操作偏好**：什么时候用它、先调哪个接口、怎么判断、要注意什么。
它按**登录账号**隔离（`admin_users`），别人既看不到也用不到。

两个入口：

- 聊天页输入框的 **`＋` 菜单**：直接列出你的技能，勾选即加载到当前会话（已加载的技能显示在
  输入框上方，可单个卸载）；「创建技能（由本会话生成）」会让模型把当前对话整理成草稿。
- **技能库页**（`#/skills`）：分页列表、手写新建、编辑长指令、删除、跳到来源会话。

**勾选技能后可以直接发送，文字框留空也算一次提问**：技能本身就是指令，所以「发送」在空文本框
上等于「按这些技能开始做」。控制台会把这句话拼出来（`按本会话已加载的技能执行：<技能名>…`）
再发送，因此请求里没有空内容、会话转录里显示的就是模型真正收到的那句；服务端对同一个动作另有
一份兜底文案（`DefaultSkillRunText`），供直接调接口的场景使用。没有可执行的技能时，空文本框点
「发送」**不会**发出任何请求（那会是一次白花的计费调用），只在界面上说明原因；输入框的占位提示
也会跟着变——它只在真能做到时才承诺「可留空直接发送」。

生成草稿是**一次正常的计费调用**；草稿**不会自动保存**，先在草稿里编辑，点「创建并加载」
才会入库。如果模型没返回可解析的 JSON，界面会给出一份按对话自动生成的骨架并说明原因，
而不是假装生成成功。

技能被删除后，已经加载它的会话下次提问会自动忽略它，不需要手工清理（会话里留着的那个 id 因为
找不到内容而被跳过；如果它是这个会话唯一的技能，空文本框的「发送」就会按上面那条规则被拒绝）。
技能库本身不限量，单个技能默认不超过 16 KiB，一个会话最多加载 12 个（见配置）。

## 8. 中断与恢复

- 每一轮问答带一个**幂等 id**：网络抖动导致重复提交时，服务端返回既有结果，不会重复计费。
- 执行工具调用前，服务端先写一条 `pending` 记录；进程崩溃或断线后，这条记录会变成
  `unknown` 并在界面上说明「这一步可能已经执行」，**不会自动重放**写操作。
- 重启后仍在「进行中」的轮次会被标记为 `interrupted`，继续追问会开始新的一轮。

## 9. 配置

```yaml
chat:
  enabled: true
  max_steps: 0                  # 0 = 不限制：一次提问会一直进行到模型不再调用工具为止
  max_tool_calls: 0             # 0 = 不限制
  max_tool_result_bytes: 65536
  max_history_messages: 40
  max_history_bytes: 262144
  max_loaded_skills: 12         # 每个会话加载上限；技能库本身不限量
  max_skill_bytes: 16384
  record_reasoning: true        # 是否把思考过程随消息保存（仍不进全局日志）
  artifact_max_bytes: 262144
  artifact_max_per_session: 50
  artifact_ticket_ttl: 5m       # 预览票据有效期
  artifact_allow_network: false # 是否允许预览页加载外部 CDN
  ui_bridge_enabled: true       # 是否允许「可交互预览」（表单提交回会话，每次提交都计费）
  max_output_tokens: 0          # 0 = 用供应商默认值
  system_prompt: ""             # 空 = 内置指令
```

`GW_CHAT_ENABLED` 可覆盖开关；联网开关与交互开关只放在 YAML，避免被环境变量误开。
`chat.enabled: false` 时两个页面显示「已禁用」，接口返回 501。

**`ui_bridge_enabled: false` 意味着什么**：预览退回只读——服务端不再给页面注入与控制台通信的
脚本，页面里的按钮不会产生任何模型请求（预览、复制源码、新标签打开都照常）。它是一道**部署级**
开关，不是「关掉模型写表单的能力」：模型仍然可能输出表单，只是提交没有出口。

**权限模型**：智能问答是一个 MCP 客户端，没有自己的权限开关。新建会话时必须选一个 MCP 令牌，
工具面与可执行范围完全由该令牌的 scope 决定（`query` 只查本账户用量；`admin_read` 可读后台只读接口；
`admin` 等同管理员凭据，可发 Key、动账、删除）。令牌被撤销或过期后，会话的下一次工具调用立即失效。
想收紧就换 scope 更小的令牌，想收回权限就在「MCP 令牌」页撤销该令牌。后台能力要求
`mcp.enabled` 与 `mcp.admin_tools` 同时为 `true`（聊天走的就是 `/mcp`）。
发凭据类接口的明文只返回一次，并会留在会话记录里——返回后请立刻保存，并在不需要时收回。

**关于「不限制次数」**：`max_steps` 与 `max_tool_calls` 默认都是 `0`（不限制），
一次提问会一直进行到模型不再调用工具为止——多步查证、边查边改都不会被中途截断。
代价是**一次点击花多少取决于模型**：每多一步就是一条计费的模型请求，
所以只有在你确实需要「一口气查完」时才留 0；想让单次点击的花费有上界，
把这两个值设成正整数（例如 16 / 32），达到上限时会停止并在页面提示。
无论设不设上限，都可以随时点「停止」，已经生成的内容与已经产生的费用照常保留。

## 10. 自查：交互能力（内联表单与交互预览）

换了二进制、改了配置之后，不必靠"点一遍看看"来判断。仓库里有一个只读的自查脚本：

```sh
GW_ADMIN_PASSWORD='你的管理员密码' scripts/verify-m34.sh        # 默认打 127.0.0.1:8088
BASE=http://127.0.0.1:8099 GW_ADMIN_PASSWORD='…' scripts/verify-m34.sh
```

它做 29 项检查，全部走真实 HTTP，覆盖的都是**不需要模型**也能确认的服务端行为：控制台资源是
新版、只读票据没有通道、`?bridge=1` 不能升权、交互票据会注入脚本且 CSP 授权了 nonce、两次响应的
token 与 nonce 各不相同、同一个代码块重复预览复用同一行 id、SVG 拒绝交互、登出后票据立即 404。
**内联表单不在这份自查里**：它没有票据、没有注入、没有任何服务端新端点——它由控制台自己的资源
渲染，接的是既有的轮次端点，因此它的覆盖在 `make ui-check` 的 `form` 视图（65 项）。

副作用只有一个临时 MCP 令牌和一个会话，**结束自动删除**（`KEEP=1` 可保留现场）；不新建账户、
不新建 Key、不产生任何模型调用，所以不花钱。失败时退出码非 0，可以直接放进运维脚本。

它管不到的是"模型会不会真的输出表单/整页页面"——那只能人工走查，见下一节。

M40 起还有一组**不需要模型**也能跑的自查（构造期守卫 + 契约测试），改工具说明时它们就是验收标准：

```sh
go test ./internal/mcpsrv/ ./internal/httpapi/     # 工具说明完整性 + 价格示例真的能写进去
```

`TestMCPPricingExampleIsWritable` 走的是模型该走的那条路：从 `admin_describe` 取示例 →
`admin_validate_pricing` 校验 → `admin_upsert_provider_model` / `admin_upsert_model` 真实写库。
说明与写入口径一旦漂移，它就会红，而不是等到运维在对话框里发现模型拒绝干活。

## 11. 排障

| 现象 | 原因与处理 |
| --- | --- |
| 提问按钮没反应 / 提示未绑定 | 会话没有绑定账户与 Key，打开「会话设置」补上 |
| `403 只有管理员可以…` | 当前登录是 `viewer`：viewer 不能发起计费请求 |
| `401` / `402` | 绑定的 Key 被停用或过期，或账户被挂起/余额不足 |
| 回答里说「本轮没有 MCP 工具」 | 该模型不支持工具调用，或被路由降级去掉了 tools（响应里标注了 `degraded`） |
| 图表显示成原始 JSON | 规格非法或超过 8 序列 / 500 点，界面里写了具体原因 |
| 预览白屏 | 页面引用了 CDN 或外链资源，被沙箱 CSP 拦住；这一点在预览窗上方有提示 |
| 预览提示「链接已过期」 | 预览票据默认 5 分钟有效；重新点「预览」即可，重新签发不额外计费 |
| 工具栏一直是「等待页面握手」 | 模型的页面脚本被沙箱安全策略拦掉了（页面里的 CSP 元标签、或浏览器不支持注入所需策略）。预览仍可查看，但无法交互；重新生成一次页面通常就好 |
| 工具栏显示「不可交互」且**没有**计数 | 交互通道没建起来。状态栏那句话会说是哪一种：说"部署关闭"就是 `chat.ui_bridge_enabled=false`；说"脚本没有回应"就是页面里的 CSP 元标签把注入脚本一起拦了（模型的页面自带 `<meta http-equiv="Content-Security-Policy">` 时会发生） |
| 提交按钮点了没反应、计数不动 | 页面没走桥接：表单按钮要是 `<button type="submit">`，自定义按钮要带 `data-aigw-send` |
| 提交后提示「过于频繁」/「已达上限」 | 见第 5 节的限额表：重新预览可重置计数 |
| 提交后模型回答里说收不到数据 | 表单字段缺 `name`：没有 `name` 的控件不会进入提交数据 |
| 工具栏「加载新版本」出现但界面没变 | 设计如此：换页会清空已填内容，必须由你点它 |
| 页面提示「交互预览已被部署关闭」 | `chat.ui_bridge_enabled: false`：只读预览照常，页面里的按钮不会产生请求 |
| `form` 代码块显示成原始 JSON 并附一句「表单未渲染」 | 规格有问题，原因就写在那句话里（未知类型、缺 `name`/`label`、选项重复、默认值不在选项里……）。改一次提问即可；控制台不会画半张表单 |
| 模型写了 `password` 字段 | 被明确拒绝：表单值会进入会话转录，凭据不走表单。排障里看到这句说明模型需要改用确认流程 |
| 表单提交按钮点了没反应 | 提交中表单会禁用（显示「模型正在处理…」）；一轮只允许一次提交，还在回答时再点会**排队**而不是并发 |
| 表单提示「超过上限」 | 一次提交最多 8 KiB。字段多、内容长时会到；减少内容后重提，或分两次问 |
| 提交后表单被填上了我没填的值 | 这是模型的界面指令在**原地更新**表单（把查到的值填回字段）。原始规格在表单下方「查看表单规格」里可核对 |
| 表单底部出现「部分未生效：… 没有节点匹配 …」 | 指令里有一条 target 在表单里不存在（最常见的是模型写了 `button[type=submit]`，内联表单的按钮是 `type=button`）。其余几条照常生效；提示条只报没落地的那几条。第 4 节列了三种可用 id |
| 模型说「已更新界面」但界面上没变化 | 先看表单卡片的**顶部**有没有一条提示条（`.aigw-msg`），再看底部状态行有没有「未生效」。都不在就是这一轮回答里根本没有 `ui` 指令块：`ui` 代码块在转录里只作为记录保留，不会自己应用到表单上（那是给沙箱页面用的「重新应用」按钮管的事） |
| 工具调用卡片是 `unknown` | 上一次执行被中断（崩溃或断线），服务端不重放写操作，请人工确认后重做 |
| 请求日志里搜不到对话正文 | 设计如此：问答内容不进入全局日志，见第 2 节 |
