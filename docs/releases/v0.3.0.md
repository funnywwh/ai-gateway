# v0.3.0

相对 `v0.2.5`，本版新增请求日志的缓存用量展示、小时维度汇总及运维配置，修复根会话识别和
Codex 首次输出前的断流恢复。按仓库发布约定升级 minor：`0.2.5` → `0.3.0`。

## Git 变更

- `c72bb52`：请求日志与维度统计增加缓存命中 token 列；缓存命中已包含在输入 token 中，不重复累加。
- `bcd6f1a`：Codex 插件实时转发工具事件，只在未交付输出时对读取失败或 EOF 最多重试一次；
  完成终态后直接结束，并保留可诊断的底层错误。已经交付工具/文本事件后不重放。
- `4b1c32e`：请求日志优先使用显式根会话标识，兼容请求头及缓存键回退，改善会话分组准确性。
- M41：维度统计改为小时汇总与实时补算，保留八维交叉筛选、排序、分页；行与总数来自同一快照。
  请求数、已计量数按请求去重，token 与费用累计全部上游尝试。新增回填、版本失效、恢复及诊断机制。

## 升级与运行

- 网关与 `provider-codex` 插件都应更新到本版构建物。
- 启动自动应用数据库迁移 0013，创建派生汇总表与触发器；迁移本身不扫描历史。历史按批回填，
  完成前读明细补算，不要求修改现有配置。日志清理后统计立即同步。
- `recording.dimension_rollup_enabled` 默认开启；设置为 false 或
  `GW_RECORDING_DIMENSION_ROLLUP_ENABLED=false` 可回退明细查询。关闭 `database.wal` 时也回退明细。
- `/admin/api/v1/stats` 的 `request_log.dimension_rollup` 提供有效开关、回填游标、发现完成标记、
  待处理小时数、最近成功时间和错误；`/metrics` 提供游标和待处理数。
- 缺少根标识的旧日志无法自动补回根会话关系。上游已输出内容后的网络中断仍需要客户端恢复。

## 验证与性能边界

`make verify`、format-smoke、汇总相关 race 检查和六组 10 万/100 万数据探针通过；UI harness 因
缺少 Firefox 跳过，HTTP 接口及版本徽标的非浏览器检查通过。

百万条、30 天窗口：重复会话的查询 p95 为 38.45 ms（明细 14.50 s）；每请求独立会话的 p95
为 4.26 s（明细 13.07 s）。独立会话不能压缩行数。小记录批量探针中失效触发器使写入吞吐下降
约 52%–62%；这不是上游调用端到端吞吐指标，关闭汇总配置也不移除触发器。
完整条件和结果见 [小时汇总设计](../design/request-dimension-rollups.md)。

## 回退

发版前保留旧网关、旧 Codex 插件及一致性数据库快照。二进制回退可恢复上一版行为；迁移是加法，
旧二进制仍能使用源表，但汇总表与触发器会留在数据库中。若需撤销触发器开销，应先停止服务并备份
最新数据库，再单独执行派生结构回退；不能用旧数据库快照覆盖发版后的新日志和计费记录。
部署结果、发布提交和回滚路径记录在 `docs/TODO.md`。
