# v0.3.1（2026-09-13）

修复 Codex 为同一会话生成标题时使用独立临时线程，导致请求日志会话统计拆成两组的问题。

- 对已知标题模板提取原始用户提示词指纹；同账户、API Key、工作区内，主会话首条观测请求与
  标题请求开始时间相差不超过 120 秒且仅有一个精确匹配候选时，自动将标题行归入主会话。
- 支持标题与主请求任意完成顺序，关联证据持久化。后续出现多个主会话候选时恢复原始标题线程。
- 会话筛选和小时统计同步更新；不改变上游缓存键、请求内容或计量数据。
- 迁移 0014 自动创建关联证据表及索引；日志删除级联清理证据，不扫描历史正文。

## 边界

关联是有限推断，不能替代客户端显式根会话标识。候选不唯一、缺少工作区、未知标题模板、
混合媒体、正文录制为 off/metadata 或配置了 redact_paths 时不推断。
指纹仅去除首尾空白后精确匹配；没有模糊匹配或仅按工作区合并。
若真实主线程未经过网关或在时间窗口之外，仍存在误匹配可能。
历史示例此前已人工修正，不能作为新自动规则的线上验证。

## 验证与回退

回归覆盖请求先后顺序、重复写入、候选冲突恢复、账户隔离、时间窗口、录制策略、混合媒体、
同步/批量事务、小时汇总失效和日志清理。发布执行 make verify 与 format-smoke。

二进制回退可恢复旧行为，保留数据库中的新增结构与记录；不要用旧快照覆盖升级后产生的计费数据。
已合并的历史行不会因二进制回退自动恢复，原始标题线程可从 request_title_links.source_session 审计。
详细实施记录见 ../session-grouping-fix.md。
