# 请求维度的小时汇总

## 行为与数据来源

统计只覆盖仍存在的 `request_logs`，请求数及已计量数按请求去重，token/费用累计该请求全部
`usage_records`。客户端、请求模型、路由模型、工作区、会话、调用类型、账户和 Key 八维组合保持
精确匹配。名字在读取时解析，标题取 `MAX(title)`，不引入近似聚合。

迁移 0013 创建小时状态、汇总世代、组合贡献、回填进度四张表和六个失效触发器。源数据仍是唯一
权威来源。触发器不解析计量 JSON、不更新统计总数，只推进源数据所属小时的版本；事务回滚则版本
也回滚。日志与计量任意顺序写入都被覆盖。日志身份不变的骨架重试、正文修改和忽略的重复结算不
触发失效。修改 request_id 或时间时，旧、新关联小时均失效。

## 读取与构建

查询把秒级闭区间拆成有效汇总小时与互斥的明细区间。`json_each` 传递小时世代和区间列表，避免
大量占位符及 UNION 分支数限制；明细区间驱动 `created_at` 范围索引，每个请求按 request_id 点查
上游尝试。不扫描整个窗口再排除汇总小时。统计行与不关联计量的分组计数在同一读事务里完成。

后台只有一个 DB 内刷新任务，启动运行，此后每 30 秒运行。每轮最多发现 200 批历史日志（每批
500 行，游标及发现的小时原子提交）、构建 200 个已结束小时，优先最近小时。历史发现尚未覆盖
的时间区间仍然查明细，不把历史发现游标作为查询覆盖边界。

每个小时先在读快照内获取版本，再按请求合并计量、按八维组合聚合；结果流式扫描，每 500 行写入
一个新世代。发布只做一次版本比较更新：源版本没变化才切换指针。并发变化使发布失败，旧汇总也
因版本不匹配被排除；下一轮再建。内存不积攒整个小时的组合结果，SQLite 分组临时空间仍随基数增长。

未完成世代、旧世代和失败世代在刷新前后清理：每轮前后各最多 200 批、每批 500 条贡献；先选择
非活动世代，再按世代索引删除，不能全扫有效汇总。清理和发布都遵循单进程单写池的部署约束。
读事务可继续看到删除前的快照，源数据清理后新查询立即排除旧汇总。小时状态保留作为廉价覆盖元数据。

关闭配置开关时不运行刷新且查询全部读明细，触发器继续失效跟踪。数据库关闭 WAL 时自动回退到
明细，诊断提示原因，避免后台一边持有读事务一边写暂存时争用回滚日志锁。后台停止函数取消上下文
并等待 goroutine 退出，在关闭 DB 前执行；部分暂存世代留给重启清理。

## 验证与性能探针

独立对照使用旧的直接 JOIN 聚合，仅将两个计数改为 DISTINCT 请求计数。对照覆盖八个维度、
交叉筛选、三个排序、分页、空窗口、完整/部分小时、当前小时、纯明细、全部汇总、混合、禁用。
额外覆盖日志与计量乱序、重复结算、事务回滚、迟到数据、统计字段变更、计量删除、时间移动、清理、
陈旧发布拒绝、同一读快照、旧库迁移、部分发现、未完成世代及重启恢复；EXPLAIN 钉住范围索引与计量点查。

复现命令（Go 工具链按仓库约定加载）：

```bash
source scripts/goenv.sh
DIMENSION_PROBE=1 go test ./internal/store -run '^TestDimensionRollupProbe$' -v -count=1 -timeout 30m
```

可用 `DIMENSION_PROBE_ROWS` / `DIMENSION_PROBE_SHAPE` 单独指定规模和形状。探针变量只存在于测试中，
不会改变生产查询。每种组合先测迁移 0012 的写入，再测新结构的写入；记录和计量使用同样 SQL，
每 500 个请求一批，关闭自动 checkpoint 后测量 WAL 字节，再恢复 checkpoint。用小正文隔离元数据与
触发器开销；这不是上游调用的端到端吞吐测试，也不代表大正文写入的成本比例。

查询取 30 天完整窗口，按客户端汇总、按费用排序；每条路径先预热一次，再采样十次，p50 取第 5 个、
p95 取第 10 个有序样本。每次测量校验与明细结果完全相同。重复形状每会话 100 个请求；独立形状
每请求一个会话；偏斜形状 90% 会话属于同一账户和 Key。百万重复形状要求至少 3 倍 p95 提升。

独立会话基数接近明细规模，不承诺恒定耗时；触发器增加写入成本，不能只看查询加速。

## 实现与设计差异

- 增加关闭 WAL 时自动回退准确明细查询，避免回滚日志模式下后台读快照与暂存写入互相阻塞。
- 将暂存版本独立为世代表，使中断版本和空小时也具有可清理、可发布的明确身份；失效小时继续使用原始数据。
- 为每轮发现、构建和清理设置批次数上限，生产按 30 秒调度持续追赶；性能探针连续执行刷新，不将其耗时冒充上线回填总时长。
